# 常见问题与答案

1. **为什么选择 LangChain？** 它提供标准化模型、工具和消息抽象，便于把 DeepSeek/OpenAI 兼容模型替换而不重写业务层。
2. **为什么使用 LangGraph？** 预约有收集、确认、完成等确定性阶段；图状态让流程可解释，避免完全依赖模型自由发挥。
3. **Agent 与普通聊天机器人有什么区别？** 聊天机器人主要生成文字；Agent 会基于目标选择工具、读取事实并执行受控业务动作。
4. **如何防止模型编造价格？** 系统提示要求事实来自工具；`get_services` 读取当前配置；真正写库时后端再次按服务 ID 校验。
5. **如何防止编造时段？** Agent 必须调用 `check_availability`，后端以配置、当前时间和数据库占用计算结果，创建时再次校验。
6. **如何避免重复预约？** HTTP 接口支持显式 `Idempotency-Key`，相同键返回最初的不可变响应快照。
7. **为什么不能用业务字段哈希做永久幂等？** 用户取消后可能合法地重新预约相同信息；永久哈希会错误命中旧记录。
8. **如何处理多人抢同一时段？** SQLite 部分唯一索引只允许一个 `confirmed` 记录占用日期+时段，并发失败返回冲突。
9. **如何确认客户真的同意？** Agent 必须先完整复述；`create_booking` 工具要求 `customer_confirmed=true`，否则拒绝写入。
10. **为什么使用 SQLite？** 单机考核 Demo 部署零依赖、事务和唯一约束可靠；正式多实例再迁移 PostgreSQL。
11. **取消如何释放时段？** 记录状态改为 `cancelled`；唯一索引只约束 `confirmed`，因此时段立即可重新预约。
12. **改期为什么安全？** 改期复用创建预约的日期、时段、服务时长规则，并在事务更新时接受唯一索引兜底。
13. **如何接入真实电话？** 后续接 SIP/Twilio/云通信，把电话音频流接入 STT→Agent→TTS，并补充转人工和录音告知。
14. **如何接入短信？** 在预约事务成功后写入可靠消息队列，由短信适配器异步发送并记录回执；当前 Demo 不做发送承诺。
15. **如何实现网站信息采集？** 获得授权后抓取公开页，保留 URL、时间和原文引用，结构化抽取后必须人工审核；失败时人工录入。
16. **如何保护客户隐私？** 最小化采集、运营视图脱敏、密钥只放 `.env`、数据库不提交；正式环境再加密、权限与审计。
17. **模型不可用怎么办？** 页面自动使用本地可靠流程，后端业务接口和数据库不依赖模型，仍可完成基础预约。
18. **语音识别不准确怎么办？** 展示识别文本让客户确认，关键手机号用格式校验；SenseVoice失败可回退浏览器识别或文字。
19. **STT状态为什么区分配置和就绪？** 配置了模型名不代表模型成功加载；接口暴露 loading/ready/error，避免误导演示者。
20. **如何实现客户交付？** 申请、授权、采集、审核、配置、测试、验收、激活后，再在正式范围交付账号和电话渠道。
21. **配置更新后 Agent 怎么同步？** 配置内容生成版本哈希，Agent 缓存签名包含该版本，下一次请求自动重建。
22. **为什么后端还要校验？** 提示词不是安全边界；前端、模型或直接 API 都可能给错误输入，唯一可信边界是确定性服务层。
23. **当前 Demo 与正式产品差距？** 缺真实电话、短信、支付、多租户、细粒度权限、监控告警、灾备和合规数据生命周期。
24. **为什么不直接上复杂微服务？** 考核关注业务理解和可运行效果；单体更易演示，边界清晰后再按负载拆分。
25. **如何评价 Agent 效果？** 离线测试工具选择与字段准确率，在线观察成功率、重问率、冲突恢复率、转人工率和延迟。
