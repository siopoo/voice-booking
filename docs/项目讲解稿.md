# 5分钟项目讲解稿

大家好，这是 PawPilot AI语音预约系统。它解决的不是单纯网页聊天，而是宠物服务门店漏接咨询、人工反复确认服务与时间、预约记录分散的问题。

CallPilot 类型产品首先要完成客户开通：客户提交企业资料和三项授权；系统整理授权范围内的公开网站信息；人工审核后生成包含服务、价格、时长、营业时间和预约规则的门店配置；再进行文本、语音和业务可靠性测试；客户验收后激活 Demo。提交申请不代表电话号码已开通，真实电话渠道属于后续商业交付。

技术上我把自然语言与业务事实分开。LangChain Agent 负责理解用户意图、决定下一步和组织自然回复；八个工具负责读取门店事实、维护草稿、查询真实时段以及创建、查询、改期、取消预约；LangGraph 的确定性状态用于判断信息是否齐全、是否等待确认、是否完成。价格和时段不写在模型记忆里，因此模型不能凭空编造。

完整链路是：浏览器麦克风进入 SenseVoice 或浏览器识别，得到文字；文字进入大模型 Agent；Agent 调用门店配置和 SQLite 工具；后端统一校验手机号、上海时区、14天窗口、休息日、过期时段、服务结束时间和并发唯一约束；只有完整复述并获得明确确认后才写库；最后浏览器语音合成播报回复。页面同步展示草稿、流程阶段、工具轨迹、耗时和预约编号，方便解释而不是隐藏 Agent 行为。

可靠性方面，`Idempotency-Key` 对单次确认保持不变，重复请求重放不可变结果；新会话使用新键，所以取消后可以重新预约。数据库的部分唯一索引保证多人抢同一时段只有一人成功。取消只改变状态并释放唯一约束，运营列表默认脱敏手机号。

没有 API Key 时，本地固定流程仍可完成核心预约；SenseVoice 加载失败会显示真实错误并回退浏览器语音或文字。当前边界是本地单门店 Demo，没有真实电话、短信和支付。后续可接 SIP/Twilio、短信供应商、CRM、多租户配置版本和人工转接，但不需要改变“Agent 决策、工具执行、业务校验兜底”的核心架构。
