# 现场演示脚本（5～10分钟）

## 演示A：客户开通与交付（约2分钟）

1. 打开 `http://127.0.0.1:8000/delivery.html`。话术：“客户不是拿到链接就直接上线，先提交资料与三项授权；申请不等于开通电话。”
2. 使用预填的“星球宠物美容”提交。预期：生成 `APP-...`，状态“已提交”。
3. 点“整理网站公开信息”。话术：“外网失败时有人工录入回退，不影响现场。”预期：状态“资料采集中”。
4. 点“人工审核通过”。预期：等待人工审核阶段完成，可编辑 JSON 配置。
5. 修改一个服务价格或欢迎语，点“确认并生成配置”，再点“进入测试阶段”。
6. 勾选七项检查，提交验收，激活 Demo。预期：“Demo已激活”，不出现电话号码已开通承诺。
7. 打开预约主页。预期：新门店名称、服务和价格立即同步。

## 演示B：AI创建预约（约3分钟）

逐句输入或说：

1. “你们有哪些服务和价格？”预期调用 `get_services`。
2. “我想给可乐预约明天下午的美容。”预期更新草稿并调用 `check_availability`。
3. “联系人陈女士，手机号13800138000。”预期调用 `update_booking_draft`。
4. 在确认前说：“换成另一个可用时间。”预期重新查时段、更新草稿并完整复述。
5. “确认预约。”预期调用 `create_booking`，页面展示编号与已确认状态。

讲解重点：“模型只负责理解和决定调用哪个工具；价格、时段与写库都由后端事实和规则决定。”

## 演示C：业务可靠性（约2分钟）

1. 新会话抢同一时段。预期：409冲突/Agent重新提供空闲时段。
2. “查询预约编号 PP...，手机号13800138000。”预期调用 `find_bookings`。
3. 要求改期，明确确认。预期先 `check_availability` 后 `reschedule_booking`，旧时段释放。
4. 要求取消，明确确认。预期 `cancel_booking`，运营列表显示“已取消”。
5. 再查原时段。预期重新可用；新幂等键可创建新预约。

## 异常备用方案

- 大模型连接失败：指出页面“本地可靠模式”，用快捷按钮完整走预约。
- SenseVoice未加载：使用 Edge/Chrome 浏览器语音识别；仍失败则文字输入。
- 外部官网不可达：使用交付页稳定演示数据与人工回退。
- 端口占用：运行 `$env:PAWPILOT_PORT` 不受支持时先停止旧 `server.py` 进程，再重新启动。
- 已激活测试配置不适合继续：恢复 `config/business.json` 的默认内容或重新走交付页激活默认配置。
