# PawPilot AI语音预约系统：客户开通与交付流程

## 1. 适用客户与业务目标

目标客户包括宠物美容店、宠物日托、宠物诊所和上门宠物美容团队。系统的价值不是“做一个会聊天的网页”，而是把客户公开业务资料转成可审计的门店配置，再让 AI 前台通过确定性工具查询服务、校验时段并写入预约。

## 2. 完整流程

```mermaid
flowchart LR
    A[客户提交 Demo 申请] --> B[授权范围内采集公开网站信息]
    B --> C[人工审核资料与代表身份]
    C --> D[生成门店业务配置]
    D --> E[配置服务/价格/时长/营业时间/休息日/时段]
    E --> F[按配置生成 Agent 提示词]
    F --> G[文字预约测试]
    G --> H[语音预约测试]
    H --> I[功能验收]
    I --> J[客户确认]
    J --> K[激活 Demo]
    K -.正式商业交付.-> L[交付账号/系统配置/电话渠道]
    L --> M[通话与预约记录/异常转人工/持续优化]
```

### 阶段一：申请

客户提交企业名称、业务类型、官网地址、社交媒体主页、服务与价格、联系邮箱、联系电话和演示语言，并明确勾选：网站内容使用授权、联系授权、企业代表身份确认。三项缺一不可。提交 Demo 申请只创建内部审核记录，**不等于立即开通电话号码**。

### 阶段二：信息采集与人工审核

团队仅在授权范围内整理网站公开信息，并记录信息来源。外部网站不可访问时使用客户填报或人工录入，不让现场演示依赖外网。人工审核联系方式、业务一致性、授权和是否允许进入配置阶段。

### 阶段三：配置生成

审核人员将资料转换为 `config/business.json`：门店名称、地址、服务、价格、时长、营业时间、休息日、可选时段、预约窗口、欢迎语和语言。后端、前端和 Agent 读取同一版本；激活后 Agent 缓存按配置版本重建。

### 阶段四：测试与验收

依次确认门店资料、服务价格、营业时间、Agent 配置；执行文字与语音预约；验证确认前不落库、并发冲突、查询、改期、取消和时段释放；最后取得客户验收。

### 阶段五：交付与运营

当前 Demo 激活的是门店配置。正式商业交付还需交付客户账号、权限、系统配置和真实电话渠道。上线后持续查看通话记录、预约记录、失败原因，配置异常转人工并迭代提示词和业务规则。

## 3. 当前实现与商业范围

| 环节 | 当前项目 | 正式商业交付 |
|---|---|---|
| 申请、授权、状态流转 | 已实现，SQLite 持久化 | 接 CRM、企业认证与权限 |
| 网站信息采集 | 稳定演示数据 + 人工回退 | 合规爬取、来源引用与定期同步 |
| 配置与激活 | 已实现，单门店配置 | 多租户、版本审批与回滚 |
| 文本/浏览器语音/SenseVoice | 已实现并可回退 | 电话线路、实时流式语音、录音合规 |
| 预约增删改查 | 已实现 SQLite 业务闭环 | 对接门店 CRM/日历/POS |
| 短信、支付、真实电话 | 未实现且页面不做承诺 | 供应商接入、计费、风控与监控 |
