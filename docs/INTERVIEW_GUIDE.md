# 面试讲解指南

## 建议的 8–10 分钟演示

1. 打开首页，说明可靠模式不依赖 API Key，先完成一次新建预约。
2. 在运营记录中展示手机号脱敏、预约编号和数据库持久化。
3. 查询该预约，演示未确认不能改期；确认后改期成功、旧时段释放。
4. 取消预约并展示同一时段可以重新预约。
5. 切到真实 Agent 模式，展示模型只负责理解与播报，LangGraph 控制业务阶段。
6. 打开 Agent trace，指出 `collect -> availability -> confirmation -> create`。
7. 用“好吧”演示不会创建，再用“确认预约”演示只写一次。
8. 展示 `python -m evals.run_evals` 的 30/30 与三个安全指标。
9. 展示目录分层、Dockerfile 和 CI，说明它不是单文件原型。
10. 最后讲生产化路径：PostgreSQL、持久化 checkpointer、认证、监控和人工接管。

## 10 个可重点讲的工程亮点

1. **确定性控制面**：LangGraph 而不是 LLM 决定何时查时段、何时确认、何时写库。
2. **单一状态源**：草稿、可用性、确认、结果和错误统一在 `BookingAgentState`，可恢复、可审计。
3. **字段失效机制**：改日期/时间重新查时段，改服务同时清除价格和时长，避免陈旧状态。
4. **确认安全**：白名单明确短语、节点二次检查、Service 校验三层保护，Eval 安全率 100%。
5. **并发与幂等**：数据库条件唯一索引解决抢占，幂等响应快照解决重复提交。
6. **事实落地**：服务、价格、营业时间和可用时段来自配置/数据库，模型没有编造空间。
7. **渐进式重构**：保留 `server.py` facade 和原 API，在不停用旧功能的前提下拆成分层架构。
8. **无模型可测试**：69 个 Python 测试与 30 条 Agent Eval 默认不调用真实 LLM，CI 稳定且无费用。
9. **可观测与隐私**：request/thread/tool/stage/latency/booking 全链路字段，手机号和密钥自动脱敏。
10. **可交付性**：`.env`、健康检查、Docker Compose、数据卷、CI 和明确的运行/回滚边界。

## 高频追问

### 为什么不完全相信提示词？

提示词是软约束，模型可能受上下文、供应商或版本变化影响。确认门槛、可用性判断和写操作属于硬业务规则，必须由代码和数据库约束保证。

### 为什么还保留可靠模式？

它让考核现场在断网、模型限流或 STT 失败时仍可完整演示业务，也提供了 Agent 的确定性对照组。它不是假数据模式，两种模式使用同一 Service 和数据库。

### 为什么选 SQLite？

单机考核场景零运维、事务完整、便于检查。并发安全的关键规则已落在唯一索引；生产环境可通过 Repository 边界换成 PostgreSQL。

### 如何证明不会重复预约？

状态机已有结果就不再写；相同请求使用幂等键返回第一次的响应快照；即使两个请求并发越过应用检查，数据库条件唯一索引仍只允许一个成功。

### Agent Eval 为什么不用真实模型？

这里评测的是业务控制面，而不是某家模型的措辞。离线评测速度快、无费用、可复现；真实模型质量可以另设非阻塞的在线评测任务。

### 当前最重要的生产化改进是什么？

把会话状态和数据库迁移到共享持久层，加入认证/授权、速率限制、OpenTelemetry 与人工接管，再做故障注入和容量测试。
